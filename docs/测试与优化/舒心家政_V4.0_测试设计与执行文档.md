# 1. 测试目标

本测试文档以当前 v3.5 实现为基线。

现有自动化测试已覆盖：

- 密码校验
- 订单流程
- 越权防护
- 数据落库
- 管理查询
- v3.5 安全回归

2026-08-14 的基线结果为：

```text
pytest：26/26 PASS
```

同时现有文档明确指出：

- 不覆盖前端 UI
- 不包含 MySQL 故障注入
- 不包含数据库连接池压力
- 当前密码算法仍为 SHA-256 + 固定盐
- 部分提现、拒单、认证上传属于演示占位

因此，本版本测试策略重点是“在不破坏已有 26 项回归的基础上补齐测试层次”。

# 28. 缺陷等级

| 等级 | 定义 | 发布要求 |
|---|---|---|
| P0 | 数据泄露、权限绕过、财务错误、系统无法运行 | 必须修复 |
| P1 | 核心业务失败 | 必须修复 |
| P2 | 次要功能异常 | 原则上修复 |
| P3 | UI/体验问题 | 可排期 |

典型 P0：

```text
普通用户可以获取 admin 权限
普通用户查看别人财务
客户端控制订单最终金额
```
