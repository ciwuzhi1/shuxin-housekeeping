# 舒心家政 · 后端架构详解

> 文档时间：2026-08-05（迁移 FastAPI + MySQL 后重写）；2026-08-14（v3.5 缺陷修复批次后更新）
> 原 Express 5 + SQLite (sql.js) 架构已由 **FastAPI + MySQL** 取代，`server/` 目录已删除。

---

## 一、定位澄清

本项目有一个**真实的 FastAPI 后端**（非纯 Mock），前端 API 请求经 Vite 代理转发到后端，后端查询 MySQL 返回真实数据；请求失败时才静默降级到 `src/mock/data.ts` 的演示数据。

| 组件 | 技术 | 说明 |
|------|------|------|
| 运行时 | FastAPI + Python 3.12 (uvicorn) | 端口 3001，venv `backend/.venv` |
| 数据库 | MySQL 8.0 | 本机 `127.0.0.1:3306`，库 `housekeeping`，PyMySQL + 连接池 |
| 认证 | JWT (PyJWT) | 24h 过期，Bearer 头传递；**登录校验 SHA-256+盐密码** |
| 校验 | Pydantic v2 | 请求参数校验（camelCase 别名 → snake_case 模型） |
| 部署 | Python + 独立 MySQL 服务 | 需本机 MySQL 运行 |

### 数据链路

```
前端请求 → Vite Proxy (/api → :3001)
                      ↓
         FastAPI 路由 → MySQL 查询 → 返回真实数据
                      ↓ (失败时)
         useApiData Hook → Mock 数据（降级，页面显示黄色 Mock 标签）
```

## 二、整体架构图

```
┌─ 前端 (React + Vite :3000) ──────────────────────┐
│  src/api/index.ts     — API 请求层 (fetch + JWT)   │
│  src/hooks/useApiData — 统一数据获取 (API→Mock)    │
│  src/store/AuthContext — 认证状态管理               │
└──────────────┬─────────────────────────────────────┘
               │  Vite Proxy (/api → :3001)
               ▼
┌─ FastAPI 服务器 (:3001) ──────────────────────────┐
│  main.py：CORS / 限流 / 统一异常 / lifespan(建表+种子)│
│  routers/：10 个业务路由（Depends 依赖注入鉴权）      │
│  database.py：PyMySQL 连接池 + to_camel + 事务       │
│  auth.py：JWT 签发/校验 + require_auth/require_role  │
│  errors.py：AppError 体系 + 全局异常处理器            │
└────────────────────────────────────────────────────┘
```

### 路由与鉴权（`backend/app/routers/`）

| 前缀 | 鉴权 | 文件 |
|------|------|------|
| `/api/auth` | 公开（登录/注册；v3.5：注册仅 client/provider，admin 禁止公开注册）；`GET /api/auth/me` 需登录 | `routers/auth.py` |
| `/api/categories` | 公开 | `routers/categories.py` |
| `/api/providers` | 列表公开（v3.5：余额字段仅本人/admin 可见）；status/verify/reject 需登录+角色 | `routers/providers.py` |
| `/api/orders` | 需登录（角色+归属双重校验；v3.5：金额由服务端按目录价校验/重算；家政员可查看抢单池订单详情） | `routers/orders.py` |
| `/api/reviews` | 需登录 | `routers/reviews.py` |
| `/api/notifications` | 需登录（本人） | `routers/notifications.py` |
| `/api/finance` | 需登录（v3.5：角色过滤——客户 403、家政员仅本人流水、汇总仅 admin） | `routers/finance.py` |
| `/api/admin` | 需 admin 角色 | `routers/admin.py` |
| `/api/client` | 需 client 角色 + 本人 | `routers/client.py` |
| `/api/provider` | 需 provider 角色 + 本人 | `routers/provider.py` |

> ✅ 与原 Node 版相比，鉴权已从"路由级角色"升级为**路由级角色 + 资源级归属**双重校验（`orders.py` 的 `_assert_visible`、`client.py` 的 SELF_ONLY、`providers.py` 的本人校验）。

## 三、各模块说明

### 3.1 入口 `backend/app/main.py`

- lifespan：`init_db()`（连接池）→ `ensure_seed()`（users 表为空时写种子）。
- 中间件：CORS（允许 `http://localhost:3000`）→ 内存限流（默认 200 次/分，测试环境可关闭）→ 全局异常处理。
- `GET /api/health`：返回版本、数据库类型、各表计数、uptime。

### 3.2 配置中心 `backend/app/config.py`

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| PORT | 3001 | 服务端口 |
| DB_HOST / PORT / USER / PASSWORD / NAME | 127.0.0.1 / 3306 / root / root / housekeeping | MySQL 连接 |
| JWT_SECRET / JWT_EXPIRES | 开发内置 / 86400s | Token 签发与过期 |
| PASSWORD_SALT | 开发内置 | 密码哈希固定盐 |
| PAGE_SIZE / MAX_PAGE_SIZE | 20 / 100 | 分页 |
| RATE_LIMIT_MAX | 200次/分 | 限流阈值（≥100000 视为关闭） |
| CORS_ORIGIN | http://localhost:3000 | 允许跨域来源 |

### 3.3 认证 `backend/app/auth.py`

- 密码：`hash_password()` = SHA-256(固定盐 + 明文)，登录时 `verify_password()` 比对。
- JWT 载荷：`{ userId, username, role }`，`sign_token` / `decode_token`。
- 依赖注入：`require_auth`（无 token→401）、`require_role(*roles)`（角色不符→403）。
- v3.5 新增 `GET /api/auth/me`：凭 token 返回当前用户（前端刷新页面后恢复会话，解决"刷新即登出"）；`register` 拒绝 admin 角色（注册入口仅 client/provider）。

### 3.4 数据层 `backend/app/database.py`

核心约定（对齐原 `database.ts`）：
1. **字段命名契约**：存储层 snake_case ↔ 对外 camelCase，由 `to_camel()` 统一转换。
2. **JSON 文本列**：`skills` / `service_area` / `*_images` 读取时自动反序列化。
3. **连接池**：`dbutils.PooledDB`（max 20 / min 1），读写自动取放连接。
4. **事务**：`transaction(fn)` 包装 START TRANSACTION / COMMIT / ROLLBACK。

### 3.5 错误处理 `backend/app/errors.py`

```
AppError → BadRequest(400)/Unauthorized(401)/Forbidden(403)/NotFound(404)/Conflict(409)/Validation(422)
```
统一响应 `{ success: false, code, message }`；`RequestValidationError` 转为 `{ path, message }` 列表；兜底 500。

### 3.6 业务路由

- **订单状态机**（`routers/orders.py` + `state_machine.py`）：`pending → accepted → in_progress → completed`，`pending/accepted → cancelled`。
  - `completed` 时结算：家政员 `completed_orders+1`、`balance+金额`，并 **INSERT income 流水**（修复 P1-2）。
  - `cancelled` 且已支付：置 refunded 并 **INSERT refund 流水**。
  - 评价（`POST /:id/review`）：仅 completed 订单、仅客户本人、不可重复；事务内 **INSERT reviews 表**（修复 P1-1）并重算家政员均分。
  - 归属校验：client 只能取消自己的订单；provider 只能操作指派给自己的订单（`_assert_visible`；v3.5 起家政员可查看抢单池中未分配的 pending 订单详情，与列表一致）。
  - **金额可信（v3.5）**：下单时服务端按 `service_category + service_name` 匹配服务目录价——单价与目录不一致 → 400；订单金额由服务端按 `目录价 × total_hours` 重算，客户端提交的金额不生效。
  - **财务角色过滤（v3.5）**：`/api/finance/transactions`——admin 全平台、provider 仅本人订单相关（JOIN orders 过滤）、client 403；`/api/finance/summary`——仅 admin。

### 3.7 校验层 `backend/app/schemas.py`

Pydantic v2，字段 snake_case 存储、通过 `alias_generator` 接收 camelCase 输入（与前端契约一致）。`LoginIn` **必带 password**（修复 P0-1）；`OrderStatusUpdate.status` 用 Literal 约束。

## 四、安全现状（迁移后，2026-08-05；v3.5 更新于 2026-08-14）

原审计确认的 P0-P2 缺陷已全部修复：

| 原缺陷 | 现状 |
|--------|------|
| 登录不校验密码 | ✅ SHA-256 + 固定盐校验；错误密码 401、缺失 422 |
| 越权读取他人数据 | ✅ client/provider 只能访问自己的订单/统计（403） |
| 越权修改订单状态 | ✅ 按角色 + 归属授权 |
| 公开接口缺鉴权 | ✅ 上下线切换需登录 + 本人 |
| 评价不落库 | ✅ 事务双写 reviews 表 |
| 流水不落库 | ✅ 完成→income、取消已付→refund |
| 构建失败 | ✅ `npm run build` 通过 |

**v3.5 新增安全修复（2026-08-14）**：

| 缺陷 | 修复 |
|------|------|
| 任何人可注册管理员账号 | ✅ 注册仅限 client/provider（Pydantic Literal + 路由兜底），前端移除管理员注册入口 |
| 订单金额可被客户端篡改 | ✅ 服务端按目录价校验单价、重算金额，篡改请求 400 |
| 任意登录用户可看全平台财务 | ✅ transactions 按角色过滤（客户 403 / 家政员本人 / admin 全量）；summary 仅 admin |
| 公开接口泄露家政员余额 | ✅ 列表/详情对非本人、非 admin 隐藏 balance |
| 刷新页面即登出 | ✅ 新增 /api/auth/me 恢复会话 |
| 注册失败伪装成功 | ✅ 后端明确失败时如实提示，仅网络层降级离线演示 |

**剩余可改进项**（非缺陷）：密码采用 SHA-256+固定盐（简单档，未用 bcrypt）；JWT 密钥为开发默认值（生产需环境变量覆盖）；无迁移机制。

## 五、架构局限（结构性，非 bug）

| 局限 | 说明 |
|------|------|
| 无独立 service 层 | 路由 handler 内联 SQL + 业务逻辑，难单测、难复用 |
| 无迁移机制 | schema 变更需删库重建，会丢数据 |
| 无 ORM | 手写参数化 SQL（PyMySQL），换取控制力与可读性 |
| 密码哈希为简单档 | 生产环境建议升级 bcrypt/argon2 |
| 静态数据混入统计 | 部分图表趋势仍为前端静态展示（非后端伪造） |

## 六、请求链路示例

客户点击「我的订单」：
```
1. 浏览器 GET /api/orders?clientId=c1 + Authorization: Bearer xxx
2. Vite Proxy → localhost:3001
3. FastAPI：CORS → 限流 → require_auth 解析 JWT → user
4. orders.py 按角色强制归属（client → clientId = user.userId）
5. database.py 执行参数化 SQL → to_camel() → 返回 camelCase 数据
6. 响应 { success, data, pagination }
7. useApiData → setData → 渲染
```
后端不可用时（步骤 4-5 失败）：`useApiData` catch → 静默使用 `mock/data.ts`，页面显示黄色 "Mock" 标签。
