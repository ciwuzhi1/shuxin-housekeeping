# 配置说明

> 本文档面向第一次克隆本项目的开发者,详细列出运行「舒心家政服务平台」所需的全部配置。
> 5 分钟快速上手请看根目录 [REQUEST.md](../../REQUEST.md) 与 [README.md](../../README.md)。

---

## 1. 环境要求

| 组件 | 版本要求 | 说明 |
|------|----------|------|
| Node.js | >= 18 | 前端构建与开发服务器 |
| npm | 随 Node 附带 | 前端依赖安装 |
| Python | 3.12 | 后端运行时(3.10+ 一般可用,未验证) |
| MySQL | 8.0 | 本机运行,默认端口 3306 |

> 项目为本地轻量部署设计,不依赖 Redis / Docker 等额外组件。

---

## 2. 安装依赖

### 2.1 前端

```bash
cd 家政
npm install
```

主要依赖:React 18、React Router v6、TypeScript 5、Vite 5、Tailwind CSS 3(完整清单见根目录 `package.json`)。

### 2.2 后端

```bash
# 首次:在 backend/ 下创建虚拟环境
python -m venv backend/.venv

# 安装依赖(版本已固定,见 backend/requirements.txt)
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
```

主要依赖:FastAPI、Uvicorn、PyMySQL + DBUtils(连接池)、PyJWT、python-dotenv;测试用 pytest + httpx。

> Windows 下的路径写法为 `backend\.venv\Scripts\python.exe`,Git Bash 中用 `/` 即可。

## 3. 环境变量配置

1. 复制根目录 `.env.example` 为 `.env`:

```bash
cp .env.example .env
```

2. 按需修改。后端启动时通过 python-dotenv 自动加载 `.env`(存在才加载,不覆盖系统已设置的变量);未设置的变量使用内置默认值。

| 变量 | 默认值 | 说明 | 何时必须修改 |
|------|--------|------|--------------|
| `PORT` | `3001` | 后端监听端口 | 端口冲突时 |
| `DB_HOST` | `127.0.0.1` | MySQL 地址 | 数据库不在本机时 |
| `DB_PORT` | `3306` | MySQL 端口 | 非默认端口时 |
| `DB_USER` | `root` | 数据库用户 | 生产环境 |
| `DB_PASSWORD` | `root` | 数据库密码 | **生产环境必须修改** |
| `DB_NAME` | `housekeeping` | 业务库名 | 多项目共用 MySQL 时 |
| `JWT_SECRET` | 开发默认值 | JWT 签名密钥 | **生产环境必须改为强随机串** |
| `JWT_EXPIRES` | `86400` | Token 有效期(秒) | 需要更短会话时 |
| `PASSWORD_SALT` | 开发默认值 | 旧格式密码哈希校验盐(v4.0 起仅用于校验存量 SHA-256 哈希,新哈希为 Argon2id 自带随机盐) | **生产环境必须修改** |
| `PAGE_SIZE` | `20` | 默认分页大小 | 一般无需修改 |
| `MAX_PAGE_SIZE` | `100` | 单页上限 | 一般无需修改 |
| `RATE_LIMIT_MAX` | `200` | 每 IP 每分钟请求上限 | 压测时可调大 |
| `CORS_ORIGIN` | `http://localhost:3000` | 允许的前端来源 | **生产环境改为实际域名** |
| `ENABLE_DOCS` | `false` | 是否启用 /docs /redoc /openapi.json 接口文档(v4.4a 起) | 联调排查时临时开启;**生产保持关闭** |

> ⚠️ `.env` 已被 `.gitignore` 排除,不会进入仓库;仓库中只有不含真实密钥的 `.env.example`。
> ⚠️ 修改 `JWT_SECRET` 后已登录用户的旧 Token 失效需重新登录。修改 `PASSWORD_SALT` 会使**仍未升级的旧格式(SHA-256)用户**无法登录——v4.0 起用户首次登录成功即自动升级为 Argon2id(与盐无关),请尽快让存量用户完成一次登录;Argon2id 用户不受影响。

## 4. 数据库初始化

### 4.1 业务库(housekeeping)

```sql
-- 用 root 连接 MySQL 后执行
CREATE DATABASE IF NOT EXISTS housekeeping DEFAULT CHARACTER SET utf8mb4;
```

导入表结构:

```bash
mysql -u root -p housekeeping < backend/schema.sql
```

执行增量迁移(补记版本并应用 schema.sql 之后新增的结构变更,幂等可重复执行):

```bash
backend/.venv/Scripts/python.exe backend/scripts/migrate.py
```

首次启动后端时,若 `users` 表为空会自动写入种子数据(分类、服务、账号、订单等演示数据),无需手工导入。

### 4.2 存量库升级(已有数据,不删库)

直接运行迁移脚本即可,详见 `backend/migrations/README.md`:

```bash
backend/.venv/Scripts/python.exe backend/scripts/migrate.py
```

### 4.3 测试库(housekeeping_test)

由 pytest 自动创建和销毁(`DROP` + 重建 + 测试后删除),**不污染业务库**,无需手工准备。前提是数据库账号有建库权限。可用环境变量 `HOUSEKEEPING_TEST_DB` 覆盖库名(并行测试隔离)。

## 7. 重置数据库

演示数据被改乱后可重置:

```bash
mysql -u root -p -e "DROP DATABASE IF EXISTS housekeeping; CREATE DATABASE housekeeping DEFAULT CHARACTER SET utf8mb4;"
mysql -u root -p housekeeping < backend/schema.sql
backend/.venv/Scripts/python.exe backend/scripts/migrate.py
# 重启后端,users 表为空时自动重新写入种子数据
```

> v4.0 起已有轻量迁移机制(`backend/migrations/` + `backend/scripts/migrate.py`),存量库升级不再需要删库重建;"删库重建 schema"仅用于演示数据重置。生产环境一律走迁移。

## 8. 测试、构建与 CI

```bash
# 后端全量测试(独立测试库:基线 e2e 36 项 + 单元测试 + 各批次新增用例,共 73 项)
backend/.venv/Scripts/python.exe -m pytest backend -v

# 仅基线 e2e(36 项)
backend/.venv/Scripts/python.exe -m pytest backend/e2e_test.py -v

# 测试 + 覆盖率门禁(CI 同款命令,当前门槛 86%,实测 87.5%)
backend/.venv/Scripts/python.exe -m pytest backend -q --cov=backend/app --cov-fail-under=86

# 后端 lint(规则集 E4/E7/E9/F/I,见 pyproject.toml)
backend/.venv/Scripts/python.exe -m ruff check backend

# 依赖漏洞审计(pip-audit 环境扫描;CI 中先升级 pip 再审计)
backend/.venv/Scripts/python.exe -m pip_audit

# 前端构建(TypeScript 检查 + Vite 打包)
npm run build

# 前端依赖审计(本地 npmmirror 镜像不支持审计端点,在 CI 内有效)
npm audit --audit-level=high
```

**CI(`.github/workflows/ci.yml`)**:push / PR 自动执行两个 job——
- **后端**:ubuntu + MySQL 8.0 服务容器(凭据与测试代码一致,零配置)→ 安装依赖 → ruff → pip-audit → pytest(覆盖率门禁 86%);
- **前端**:Node 20 → `npm ci` → `npm run build` → `npm audit`(首轮 continue-on-error 观察,确认无噪音后转硬门禁)。

本地预演 = 同一组命令按同顺序执行。

## 9. 常见问题

| 现象 | 原因与处理 |
|------|------------|
| `/api/health` 不通 | MySQL 未启动,或 `DB_USER/DB_PASSWORD` 与本机不一致 —— 检查 `.env` |
| 前端页面显示"Mock 数据"标签 | 后端未启动或不可达,前端按设计降级为 Mock 演示数据;启动后端并刷新即可 |
| 登录报 401 | 种子数据未初始化(重置数据库后重启后端),或账号密码输错 |
| 前端 3000 端口被占用 | `npm run dev -- --port 3001` 换端口,并同步修改 `CORS_ORIGIN` |
| 后端 3001 端口被占用 | `--port 3002` 换端口,并同步修改 `vite.config.ts` 中的代理目标 |
| pytest 报连接失败 | MySQL 未运行,或账号无建库权限(需要能创建 `housekeeping_test`) |
| 中文目录下启动失败 | 建议将项目放在纯英文路径下,避免个别工具链对中文路径的兼容问题 |
