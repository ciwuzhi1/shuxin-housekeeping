# 舒心家政 · 启动说明

> 文档时间：2026-08-05（迁移 FastAPI + MySQL 后更新）；2026-08-14（v3.5 缺陷修复批次后更新）

---

## 环境要求

| 依赖 | 版本 | 说明 |
|------|------|------|
| Node.js | >= 18 | 前端 |
| Python | 3.12 | 后端（venv 位于 `backend/.venv`） |
| MySQL | 8.0 | 本机 `127.0.0.1:3306`，用户 `root`，库 `housekeeping` |

---

## 一、后端启动

```bash
cd 家政

# 首次需安装依赖（已配置则跳过）
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt

# 启动（端口 3001）
backend/.venv/Scripts/python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 3001
```

启动时会自动连接 MySQL 的 `housekeeping` 库；若 `users` 表为空则自动写入种子数据（8 用户 / 6 分类 / 21 子服务 / 9 订单 / 10 流水 / 7 通知）。

> v3.5 说明：种子订单 o4/o8 曾因 provider_id 为空而永久卡死（已分别归属 p4/p3），o5 补支付状态与 income 流水；已在 2026-08-14 对正式库执行定向修复。

## 二、前端启动

```bash
npm install
npm run dev          # → http://localhost:3000
```

Vite 将 `/api` 代理到 `http://localhost:3001`。

## 三、验证服务

```bash
curl http://localhost:3001/api/health
# → {"success":true,"stats":{"users":8,"orders":9,...}}
```

## 四、重置数据库（注意会清空数据）

```bash
# 方式一：命令行重建
mysql -u root -p -e "DROP DATABASE IF EXISTS housekeeping; CREATE DATABASE housekeeping DEFAULT CHARSET utf8mb4;"
mysql -u root -p housekeeping < backend/schema.sql
# 重启后端即可自动写入种子数据（users 表为空时触发）

# 方式二：删除库后重启后端（lifespan 中 ensure_seed 在表不存在时会报错，
# 推荐先执行 schema.sql 再重启）
```

> ⚠️ 数据库无迁移机制，schema 变更需"删库重建"，会丢失运行期产生的真实业务数据。正式使用前请备份。

## 五、运行端到端测试

```bash
cd 家政
backend/.venv/Scripts/python.exe -m pytest backend/e2e_test.py -v
```

测试使用独立测试库 `housekeeping_test`（启动时自动 DROP + 重建 + 建表 + 种子，结束自动清理），**不污染 `housekeeping` 正式库**。共 26 项断言，覆盖登录密码校验、越权防护、评价/流水落库、状态流转、结算与统计、指定家政员下单/防抢占，以及 v3.5 新增的注册管控/金额防篡改/财务角色过滤/余额可见性/会话恢复/抢单池详情可见。
