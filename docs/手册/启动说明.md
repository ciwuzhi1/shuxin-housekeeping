# 舒心家政 · 启动说明

> 文档时间：2026-08-05（迁移 FastAPI + MySQL 后更新）；2026-08-14（v3.5 缺陷修复批次后更新）；2026-08-29（v4.0 第一批：Argon2id / 迁移机制 / Service 层后更新）

---

## 环境要求

| 依赖 | 版本 | 说明 |
|------|------|------|
| Node.js | >= 18 | 前端 |
| Python | 3.12 | 后端（venv 位于 `backend/.venv`） |
| MySQL | 8.0 | 本机 `127.0.0.1:3306`，用户 `root`，库 `housekeeping` |

---

## 一、后端启动

```bash
cd 家政

# 首次需安装依赖（已配置则跳过）
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt

# 启动（端口 3001）
backend/.venv/Scripts/python.exe -m uvicorn backend.app.main:app --host 127.0.0.1 --port 3001
```

启动时会自动连接 MySQL 的 `housekeeping` 库；若 `users` 表为空则自动写入种子数据（8 用户 / 6 分类 / 21 子服务 / 9 订单 / 10 流水 / 7 通知）。

> v3.5 说明：种子订单 o4/o8 曾因 provider_id 为空而永久卡死（已分别归属 p4/p3），o5 补支付状态与 income 流水；已在 2026-08-14 对正式库执行定向修复。

## 二、前端启动

```bash
npm install
npm run dev          # → http://localhost:3000
```

Vite 将 `/api` 代理到 `http://localhost:3001`。

## 四、数据库升级与重置

### 4.1 存量库升级（保留数据，推荐）

数据库结构变更通过迁移脚本执行（v4.0 起）：

```bash
backend/.venv/Scripts/python.exe backend/scripts/migrate.py
```

- 按顺序执行 `backend/migrations/NNN_*.sql`，已应用版本记录在库内 `schema_migrations` 表，重复执行自动跳过
- 详见 `backend/migrations/README.md` 的双轨约定：**schema.sql = 全量最新结构（全新部署用）；migrations/ = 增量（存量库升级用），两者必须同步修改**

v4.3 新增三张表（settings / withdrawals / certification_files）及种子，老库就地升级：

```bash
backend/.venv/Scripts/python.exe scripts/migrate_v43.py
```

> 全新部署（schema.sql 已含 v4.3 全部表）无需执行该脚本。

### 4.2 重置数据库（注意会清空数据）

```bash
# 方式一：命令行重建
mysql -u root -p -e "DROP DATABASE IF EXISTS housekeeping; CREATE DATABASE housekeeping DEFAULT CHARSET utf8mb4;"
mysql -u root -p housekeeping < backend/schema.sql
# 重启后端即可自动写入种子数据（users 表为空时触发）

# 方式二：删除库后重启后端（lifespan 中 ensure_seed 在表不存在时会报错，
# 推荐先执行 schema.sql 再重启）
```

> ⚠️ 重建后请再执行一次 `migrate.py`（补记版本并应用 schema.sql 未包含的后续迁移）。生产环境禁止删库重建，一律走迁移。

## 五、运行自动化测试

```bash
cd 家政
backend/.venv/Scripts/python.exe -m pytest backend -v        # 全量：基线 e2e + 单元测试 + v4.0 新增用例
backend/.venv/Scripts/python.exe -m pytest backend/e2e_test.py -v   # 仅 26 项基线 e2e
```

- 测试使用独立测试库 `housekeeping_test`（启动时自动 DROP + 重建 + 建表 + 种子，结束自动清理），**不污染 `housekeeping` 正式库**；并行隔离可用环境变量 `HOUSEKEEPING_TEST_DB` 换库名
- 26 项基线 e2e：登录密码校验、越权防护、评价/流水落库、状态流转、结算与统计、指定家政员下单/防抢占，以及 v3.5 的注册管控/金额防篡改/财务角色过滤/余额可见性/会话恢复/抢单池详情可见
- v4.0 新增（位于 `backend/tests/`）：单元测试（密码哈希/JWT/状态机/分页，22 项）、旧哈希登录自动升级、种子账号三角色登录、财务幂等（重复完成单笔 income / 取消退款单笔且为负 / 唯一键拦截重复插入）、安全响应头，共 33 项
