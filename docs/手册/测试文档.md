## 第一部分：自动化测试（pytest，68 项）

### 运行方式

```bash
cd 家政
backend/.venv/Scripts/python.exe -m pytest backend -v            # 全量 73 项
backend/.venv/Scripts/python.exe -m pytest backend/e2e_test.py -v   # 仅 36 项基线 e2e
```

测试使用独立测试库 `housekeeping_test`（自动创建/清理，`HOUSEKEEPING_TEST_DB` 环境变量可换库名以支持并行隔离，v4.4a 起 e2e_test.py 与 tests/ 均遵循该变量），**不污染正式数据**。

CI（`.github/workflows/ci.yml`）在 push/PR 时以同组命令自动执行：ruff → pip-audit → `pytest backend -q --cov=backend/app --cov-fail-under=86`（MySQL 8.0 服务容器，凭据与测试硬编码一致）+ 前端 `npm ci`/`npm run build`/`npm audit`。

### 已知局限

1. 不覆盖前端 UI 渲染（依赖手工清单；生产关闭 Mock 降级的逻辑为代码审查 + 构建验证，无组件测试）；
2. 不含 MySQL 故障注入/连接池压力测试；
3. 并发用例以"条件更新 + 唯一键拦截"方式验证，未做真实多线程并发压测（locust 属后续批次）；
4. 管理端「禁用账号」仍为演示占位（后端无禁用状态），未纳入自动化断言。
